# 影视内容发行权窗口与独占冲突审阅平台

源提示词编号：10。维护作品、权利类型、地区、语言、窗口、独占和次级授权，联动时间轴与地区矩阵，检测重叠、交叉、倒挂和独占冲突，支持批量调窗、版本差异、评论锚点、审批和追溯导出。

## 技术栈

Next.js App Router、Chakra UI、Zustand、TanStack Query、tRPC、Zod、TypeScript。

## 运行

```bash
npm install
npm run dev
```

开发地址：http://localhost:62053

```bash
npm run build
npm run test:smoke
```

## 版本链规则

授权窗口、条款意见、审批包共用同一条版本链（`DraftVersion.parentId` 串联，见 `lib/versioning.ts`、`store/rights.ts`）：

1. **任一处变动生成新草案版本**：窗口编辑显式「保存为新草案版本」、批量调窗、提交意见、接受意见、关闭过期意见都会在链上追加新版本；旧版本快照不可变。
2. **意见锚定窗口版本**：每条意见记录 `windowVersionId` 与窗口 id。接受时先核对锚定版本与当前版本的窗口数据；开始/结束日期、地区、独占任一不同即拒绝合并，弹窗列出逐项差异，且不产生新版本。
3. **锚点变动自动失效**：日期、地区或独占发生变动时，锚定旧窗口版本的待处理意见自动关闭并在变更说明里记录差异（次级授权、渠道等非锚点字段不使意见失效）。
4. **审批闸门**：只接受版本链头部当前草案；存在高风险（独占冲突/窗口倒挂）或待处理意见（含锚点过期的）一律拒绝，原草案保留，阻塞明细（类型 + 窗口/意见）写入「最近一次审批」。
5. **只读快照**：审批通过后该版本固化为只读快照，页面禁用编辑；查看历史版本时接受意见/提交/审批均禁用。
6. **审批包导出与校验**：导出 JSON（`rights-approval-package/v2`）含版本号、父版本、意见处理结果（accepted/pending/closed）、窗口快照、冲突与变更清单及 FNV-1a 校验和。重新载入时先验校验和（篡改→校验失败），再比版本号/父版本/窗口数据，并对比版本链头部——包之后窗口又被改动即标记「已失效」并列出差异。

`npm run test:smoke` 覆盖上述 11 个场景。
